## Must-have features
1. Installable PWA that opens fully offline after the first online launch.
2. Media Session integration: the Dynamic Island, Lock Screen and Control Center show title, artist, album and artwork, with play, pause, previous, next and seek.
3. Downloads for offline use: audio + artwork (thumbnail) + lyrics, per song and "download all" for an album or playlist, with progress, cancel, retry and delete.
4. Offline mode: a library of downloaded songs that plays with no network.
5. Now Playing screen with synced (LRC) or plain lyrics.
6. Queue, shuffle, repeat; resume the last song and position on launch.
7. Settings: storage usage, persistent-storage status, delete downloads, debug console toggle, diagnostics.

## Architecture
- src/source/MusicSource.ts: the interface below.
- src/source/mockSource.ts: 6 sample tracks generated by a script (short WAV tones in public/mock/), with generated artwork and sample LRC lyrics. No copyrighted media.
- src/source/apiSource.ts: adapter for my backend, built from "My music source" (TODO stubs if details are missing).
- src/player/PlayerEngine.ts: owns the single audio element, the queue, shuffle and repeat.
- src/player/mediaSession.ts: metadata, action handlers, position state.
- src/storage/db.ts: IndexedDB schema and migrations.
- src/storage/blobStore.ts: OPFS when writable, otherwise IndexedDB Blobs.
- src/storage/downloadManager.ts: persistent download queue.
- src/storage/artwork.ts: resize artwork to 512x512 JPEG.
- src/lyrics/lrc.ts: LRC parser.
- src/ui/: Library, Search, Downloads, NowPlaying and Settings screens, MiniPlayer, TabBar.
- src/sw.ts: service worker.

MusicSource interface:

    interface Track { id: string; title: string; artist: string; album?: string; durationSec?: number; artworkUrl?: string }
    interface Lyrics { kind: 'lrc' | 'plain'; text: string }
    interface MusicSource {
      search(query: string): Promise<Track[]>;
      getTrack(id: string): Promise<Track>;
      getStreamUrl(id: string): Promise<string>;
      getArtworkUrl(id: string, size: number): Promise<string | null>;
      getLyrics(id: string): Promise<Lyrics | null>;
      listAlbum?(id: string): Promise<Track[]>;
      listPlaylist?(id: string): Promise<Track[]>;
    }

IndexedDB database "music-pwa", version 1:
- tracks (key: id): Track
- downloads (key: trackId): status ('queued' | 'downloading' | 'done' | 'error'), bytesDone, bytesTotal, audioKey, artworkKey, mime, downloadedAt, error
- lyrics (key: trackId): Lyrics
- blobs (key: string): Blob, fallback only
- playlists (key: id): name, trackIds
- downloadQueue (key: jobId): pending jobs
- state (key: 'player'): queue, index, positionSec, shuffle, repeat

## Requirements

### PWA shell and offline launch
- Manifest: name, short_name, id "/", start_url "/", scope "/", display "standalone", theme_color, background_color, icons 192 and 512 plus a maskable 512. Add a 180x180 apple-touch-icon link in index.html.
- Viewport meta with viewport-fit=cover. Pad the UI with env(safe-area-inset-*) so nothing sits under the Dynamic Island or the home indicator.
- Service worker: precache the whole build; serve the cached index.html for navigations; ignore requests whose destination is "audio" or "video"; cache remote artwork with StaleWhileRevalidate and catalog JSON with NetworkFirst (3-second timeout).
- When a new service worker is waiting, show an "Update available" toast; tapping it activates the new worker and reloads.
- Detect standalone mode (matchMedia('(display-mode: standalone)') or navigator.standalone). In a normal Safari tab, show a banner: install with Add to Home Screen, because downloads made in Safari won't appear in the installed app.

### Player and Dynamic Island
- Create ONE HTMLAudioElement for the app's whole life; never a new element per song. The first play must come from a tap.
- Downloaded songs play from URL.createObjectURL(blob); revoke the previous object URL on every song change. Online songs play from the stream URL.
- While a song plays, prepare the next song's URL in advance. In the 'ended' handler, set the new src and call play() immediately, with no slow awaits first, so iOS has the best chance to keep playing while locked.
- On every song change, set navigator.mediaSession.metadata: title, artist, album, artwork at 512x512.
- Register handlers for play, pause, previoustrack, nexttrack and seekto, each in try/catch. Don't register seekbackward or seekforward: on iOS they can replace the previous/next buttons (verify on device).
- Keep navigator.mediaSession.playbackState in sync. Call setPositionState({ duration, playbackRate, position }) on loadedmetadata, seeked, ratechange and about once a second while playing; skip it while duration is NaN or Infinity.
- Offline artwork: use an object URL of the stored artwork blob, inside one function with a data: URL fallback, so I can switch if iOS ignores blob artwork.
- Save player state every 5 seconds and on visibilitychange and pagehide; on launch, restore the queue and position, paused.
- On a playback error, show a toast and skip to the next song.

### Downloads and storage
- Per song: fetch the full audio file (no Range header) and report progress from the response stream; save it with its Content-Type, because Safari needs a correct audio MIME type to play blobs; then fetch and resize the artwork; then fetch the lyrics; then mark the download done.
- Audio is required: if it fails, remove any partial data and mark the job as an error. Artwork and lyrics are optional: if missing, record that and continue.
- Run 2 downloads at a time from a queue stored in IndexedDB, so it resumes after a restart. Support cancel, retry and de-duplication.
- iOS doesn't download in the background: pause the queue when the page is hidden, resume when it's visible, and show "Keep the app open while downloading".
- Before the first download, call navigator.storage.persist() from the tap that started it, and show the result in Settings.
- Show usage from navigator.storage.estimate() and each song's size; allow deleting one song or all downloads.
- Catch QuotaExceededError: stop the queue and show "Storage full" with a link to Settings. Before a large batch, compare the remaining quota with the known Content-Length total.
- blobStore: use OPFS when navigator.storage.getDirectory exists and FileSystemFileHandle.prototype.createWritable is supported; otherwise store Blobs in the IndexedDB "blobs" store. Same interface for both: put(key, blob), get(key), delete(key), size(key). Show the active backend in Diagnostics.

### Lyrics
- Parse LRC: [mm:ss.xx] timestamps, several timestamps on one line, and the [offset:] tag; ignore other tags. Fall back to plain text.
- Now Playing highlights the current line and auto-scrolls to it, pausing auto-scroll for 3 seconds after the user scrolls. Tapping a line seeks there.
- Lyrics are saved with each download and work offline.

### Offline behaviour
- Track connectivity with navigator.onLine, the online and offline events, and failed fetches.
- Offline, the library shows downloaded songs; other songs are greyed out with "Not downloaded"; search covers the local library.
- Never block the UI waiting for the network.

### UI
- Mobile-first; follows system light/dark mode; touch targets at least 44 px.
- Bottom tab bar (Library, Search, Downloads, Settings) with a mini player above it. Tapping the mini player opens Now Playing: large artwork, scrubber, controls and a lyrics toggle.
- Skeleton loaders, smooth transitions, no layout jumps.

### Debugging without a Mac
- Settings > Debug console: a toggle that lazy-loads eruda and remembers the choice.
- Settings > Diagnostics: standalone yes/no, service worker state, persistent storage yes/no, usage and quota, blob backend (OPFS or IndexedDB), and the last 50 player and Media Session events.
